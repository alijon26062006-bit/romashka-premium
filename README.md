# 🌼 Ромашка Premium — интернет-магазин цветов

Готовый коммерческий магазин цветов: премиальная витрина, корзина, оформление заказа через WhatsApp и админ-панель, в которой владелец сам добавляет букеты — без программиста.

- **Витрина** — каталог, категории, поиск, карточка букета, корзина
- **Telegram** — товары можно добавлять и удалять с телефона, там же видна посещаемость
- **Заказы** — форма с адресом доставки, готовое сообщение в WhatsApp и заявка в панели
- **Админка** — добавление букетов за минуту, загрузка фото перетаскиванием, настройки магазина
- **Поиск** — заголовки под запросы, разметка Schema.org, карта сайта, адреса с названием букета
- **Готово к серверу** — Docker, автоматический SSL, запуск одной командой

## Запуск на сервере одной командой

Нужен любой VPS с Ubuntu и домен, у которого A-запись указывает на IP сервера.

Подключитесь к серверу по SSH и вставьте **одну команду**, заменив домен на свой:

```bash
apt update && apt install -y git && git clone https://github.com/alijon26062006-bit/romashka-premium.git && cd romashka-premium && ./deploy.sh ваш-домен.tj
```

Если вы вошли не под `root`, добавьте `sudo` в начало:

```bash
sudo apt update && sudo apt install -y git && git clone https://github.com/alijon26062006-bit/romashka-premium.git && cd romashka-premium && ./deploy.sh ваш-домен.tj
```

`chmod +x` не нужен — права на запуск уже записаны в репозитории.

Скрипт сам:
1. установит Docker, если его нет;
2. создаст `.env` со **случайным паролем администратора**;
3. соберёт и запустит проект;
4. получит бесплатный SSL-сертификат Let's Encrypt (сайт сразу откроется по `https://`);
5. напечатает адрес сайта, логин и пароль.

Без домена — просто `./deploy.sh`, сайт откроется по IP сервера.

### Если на сервере уже работает nginx

Когда порты 80 и 443 заняты другим сайтом, обычный `deploy.sh` не подойдёт — Caddy не сможет их получить. Для такого сервера есть второй скрипт:

```bash
git clone https://github.com/alijon26062006-bit/romashka-premium.git && cd romashka-premium && ./deploy-nginx.sh ваш-домен
```

Что он делает:

- запускает магазин в Docker на `127.0.0.1` — наружу порт не открывается;
- сам находит свободный порт, если 3000 занят;
- добавляет **отдельный** server-блок в nginx, ничего существующего не трогая;
- ставит `client_max_body_size 10M`, иначе nginx резал бы загрузку фото на 1 МБ;
- проверяет конфиг через `nginx -t` **до** перезагрузки и откатывает изменения, если проверка не прошла;
- получает SSL через certbot, если он установлен.

Остановить только магазин, не трогая другие сайты:

```bash
docker compose -f docker-compose.nginx.yml down
```

#### Домен занят другим сайтом

Так бывает, если certbot ранее прописал ваш домен в чужой конфиг — например, когда на сервере есть блок `default_server`. Тогда nginx отдаёт домен тому сайту, и магазин не появляется.

Скрипт распознаёт это и по умолчанию **останавливается**, показывая файл и строки. Освободить домен автоматически:

```bash
./deploy-nginx.sh ваш-домен --takeover
```

В этом режиме скрипт снимет копию чужого файла, вырежет из него **только** те `server`-блоки, которые объявляют ваш домен, проверит `nginx -t` и при любой ошибке вернёт всё как было. Остальные сайты на сервере не затрагиваются.

### Бесплатный домен DuckDNS

Для теста подойдёт бесплатный поддомен с [duckdns.org](https://www.duckdns.org):

```bash
./deploy.sh ваше-имя.duckdns.org
```

SSL-сертификат выдаётся как обычно: `duckdns.org` входит в Public Suffix List, поэтому Let's Encrypt считает ваш поддомен отдельным доменом и лимиты не делятся с другими пользователями сервиса.

Что нужно проверить:

- на странице DuckDNS в поле **current ip** стоит IP вашего сервера;
- порты **80 и 443** открыты извне — без 80-го Let's Encrypt не выдаст сертификат;
- если сервер стоит дома, а не на VPS: провайдер часто блокирует входящий 80-й порт, а при CGNAT внешнего IP нет вообще. Тогда домен работать не будет — нужен VPS.

Если IP сервера **меняется**, включите автообновление: впишите в `.env`

```
DUCKDNS_SUBDOMAIN=ваше-имя
DUCKDNS_TOKEN=токен-со-страницы-duckdns
```

и запустите `./deploy.sh` снова — он сам поднимет службу, которая сообщает IP каждые 5 минут. На VPS с постоянным IP это не нужно.

### Переезд на собственный домен

Когда купите настоящий домен — направьте его A-запись на IP сервера и выполните одну команду:

```bash
./deploy.sh ваш-домен.tj
```

Новый сертификат Caddy получит сам. Каталог, фотографии и настройки останутся на месте.

### Обновление после правок

```bash
git pull && ./deploy.sh ваш-домен.tj
```

Каталог, настройки и загруженные фото хранятся в папках `data/` и `uploads/` и переживают любое обновление.

### Полезные команды

```bash
docker compose logs -f      # смотреть логи
docker compose restart      # перезапустить
docker compose down         # остановить
```

## Настройка перед публикацией

Все секреты лежат в файле `.env` (в git он не попадает). Скопируйте образец и заполните:

```bash
cp .env.example .env
```

| Переменная | Зачем нужна |
|---|---|
| `ADMIN_PASSWORD` | Пароль в админку. **Обязательно поменяйте** |
| `SITE_URL` | Ваш домен с `https://` — для ссылок в Google и превью в WhatsApp |
| `DOMAIN` | Домен для автоматического SSL в Docker |
| `PORT` | Порт сервера, по умолчанию 3000 |

Название магазина, номер WhatsApp, телефон, часы работы и город меняются **прямо в админке**, в разделе «Настройки» — трогать код не нужно.

## Поиск: Google и Яндекс

### Что уже делает сайт

| | |
|---|---|
| **Заголовки под запрос** | `Доставка цветов в Душанбе — Ромашка \| Букеты от 120 сомони`. Название города берётся из настроек и склоняется: в Душанбе, в Худжанде, в Исфаре |
| **Описания** | Собираются сами: количество букетов, цена от, доставка. Своё описание из настроек, если задано, важнее |
| **Адреса букетов** | `/bukety/17-rozovaya-mechta` вместо `product.html?id=17`. Старые ссылки живы — уводят постоянным редиректом (301), без дублей в индексе |
| **Разметка Schema.org** | Магазин (адрес, часы работы, диапазон цен, ссылки на соцсети), каталог, карточка товара с ценой и наличием, «хлебные крошки». По ней Google рисует цену и наличие прямо в выдаче |
| **Карта сайта** | `/sitemap.xml` — все страницы с датами, приоритетами и фотографиями букетов. Обновляется сама при добавлении товара |
| **robots.txt** | Указывает на карту сайта, закрывает админку |
| **Превью ссылок** | Заголовок, описание и фото при отправке в WhatsApp и соцсети |
| **Один H1 на странице** | С названием города |

Ничего настраивать не нужно — всё считается из каталога и настроек магазина.

### Что нужно сделать вам

Код отвечает за то, чтобы поисковик **понял** сайт. За то, чтобы он **узнал** о нём
и стал доверять, отвечают четыре шага. Без них новый сайт может не появляться
в выдаче месяцами.

**1. Настоящий домен вместо duckdns.org.** Это самое важное. `имя.duckdns.org` —
бесплатный общий поддомен, каких тысячи; поисковики индексируют такие адреса неохотно
и высоко не ставят, а покупатель видит в выдаче непонятный адрес. Домен в зоне `.tj`
стоит недорого, переезд — одна команда, каталог и фотографии остаются на месте:

```bash
./deploy.sh ваш-домен.tj
```

**2. Google Search Console** — [search.google.com/search-console](https://search.google.com/search-console).
Добавьте сайт, выберите способ «HTML-тег», скопируйте из него **только значение
`content`** и вставьте в админке: **Настройки → Код Google Search Console**. Сохраните,
вернитесь и нажмите «Подтвердить». Затем в разделе «Файлы Sitemap» добавьте
`sitemap.xml`. После этого сайт попадает в индекс за дни, а не за месяцы.

**3. Яндекс.Вебмастер** — [webmaster.yandex.ru](https://webmaster.yandex.ru). То же самое,
поле **Код Яндекс.Вебмастера**. В Таджикистане Яндексом пользуются заметно, пропускать
его не стоит.

**4. Google Business Profile** — [business.google.com](https://business.google.com).
Карточка организации на картах. По запросу «цветы Душанбе» карта с магазинами
показывается **выше** обычных результатов, и попасть туда новому магазину гораздо
проще, чем на первое место в общей выдаче. Нужны адрес, часы работы, телефон и фото.
Бесплатно.

### Чего ждать по времени

Первое место в Google не покупается и не программируется — его занимает сайт,
которому поисковик доверяет больше, чем остальным. Реалистично:

- **дни** — сайт появляется в поиске по названию «Ромашка Душанбе» после шага 2;
- **1–2 недели** — карточка на картах после шага 4, и по запросам вроде
  «цветы рядом» магазин уже видно;
- **2–6 месяцев** — заметные позиции по общим запросам вроде «доставка цветов Душанбе»,
  и то при живом каталоге и ссылках на сайт из Instagram и справочников.

Что помогает больше всего дальше: свои описания букетов вместо скопированных,
настоящие фотографии, ссылка на сайт в шапке Instagram и регулярное добавление
новинок — обновляющийся каталог поисковик обходит чаще.

## Оформление заказа

Раньше из корзины сразу открывался WhatsApp с одним списком букетов, а имя,
телефон и адрес приходилось выспрашивать в переписке. Теперь между корзиной и
WhatsApp стоит короткая форма, и сообщение уходит уже заполненным.

Что спрашивается:

| Поле | Обязательно | Пояснение |
|---|---|---|
| Имя | да | как обращаться к клиенту |
| Телефон | да | проверяется, что цифр хватает на настоящий номер |
| Доставка или самовывоз | — | при самовывозе поля адреса прячутся |
| Город | — | подставляется город магазина из настроек, рядом список городов Таджикистана и «Другой город» с полем для ввода |
| Улица, район | да, при доставке | |
| Дом | да, при доставке | |
| Квартира | — | |
| Ориентир | — | «возле школы №10», «зелёные ворота» |
| Когда привезти | — | «сегодня к 18:00» |
| Комментарий | — | открытка, пожелания |

Пока форма не заполнена, в WhatsApp ничего не уходит — вместо этого показывается,
что именно осталось дописать.

Введённое запоминается в браузере клиента: со второго заказа адрес уже подставлен,
набирать заново не нужно.

### Что приходит в WhatsApp

```
Здравствуйте! 🌸 Хочу оформить заказ в магазине «Ромашка».

🛍 Букеты:
• Нежная ромашка × 1 — 120 сомони
Итого: 120 сомони

👤 Имя: Алиджон
📞 Телефон: +992 90 140 32 63

🚚 Доставка
🏙 Город: Душанбе
📍 Адрес: улица Рудаки, дом 45, кв. 12
🧭 Ориентир: возле школы №10
🕒 Когда: сегодня к 18:00

💬 положите открытку
```

Одновременно заявка со всеми этими полями сохраняется в панели и в телеграм-боте —
даже если клиент передумает нажимать в WhatsApp «отправить», обращение не потеряется.

Номер, на который уходит заказ, сервер сообщает в ответе на заявку. Поэтому смена
номера из телеграма действует немедленно, даже для страниц, открытых до неё.

Все три пути к заказу — кнопка в корзине, ссылка «Заказать через WhatsApp» и кнопка
на странице букета — ведут через эту форму. Мимо неё заказ без адреса не уйдёт.

Сумму считает сервер по своим ценам: подменить её со стороны браузера нельзя.

## Панель управления в Telegram

Магазином можно управлять с телефона, не открывая админку в браузере: добавить букет,
убрать его с витрины, удалить и посмотреть, сколько людей заходило на сайт.

### Как включить

1. Напишите в Telegram боту **@BotFather** команду `/newbot` и придумайте имя.
   В ответ придёт токен — длинная строка вида `8123456789:AAE...`
2. Узнайте свой числовой id: напишите боту **@userinfobot**, он ответит числом
3. Впишите оба значения в файл `.env` на сервере:

```
TELEGRAM_BOT_TOKEN=8123456789:AAE...
TELEGRAM_ADMIN_IDS=123456789
```

4. Пересоберите магазин той же командой, которой ставили:

```bash
./deploy.sh ваш-домен          # или ./deploy-nginx.sh ваш-домен
```

Именно пересоберите, а не `docker compose restart`: значения из `.env` попадают
внутрь контейнера при его создании, и простой перезапуск подхватит старые.

Готово — откройте своего бота в Telegram и отправьте `/start`.

Если id вписать забыли, ничего страшного: бот ответит на любое сообщение и сам
подскажет ваш id. Как только список владельцев заполнен, посторонним он больше
ничего не рассказывает.

Управлять могут несколько человек — перечислите id через запятую:
`TELEGRAM_ADMIN_IDS=123456789,987654321`

### Что умеет

| Кнопка | Что делает |
|---|---|
| ➕ **Добавить товар** | Спрашивает по очереди: название → категория → цена → описание → фото. Показывает готовую карточку и сохраняет по кнопке. Букет появляется на сайте сразу |
| 📦 **Товары** | Список каталога. По нажатию — карточка с кнопками «Убрать с витрины» и «Удалить». Удаление спрашивает подтверждение и убирает заодно фотографию |
| 📊 **Статистика** | Посетители и просмотры за сегодня, вчера, 7 и 30 дней. Плюс пятёрка самых открываемых букетов и число заявок |
| 🧾 **Заявки** | Последние десять заказов: имя, телефон, состав, сумма и адрес доставки |
| ⚙️ **Настройки** | Показывает, на какой номер уходят заказы, и позволяет его сменить |

Категорию на втором шаге можно выбрать кнопкой из уже существующих или написать новую.
Описание и фото не обязательны — отправьте «`-`», чтобы пропустить.
Прервать добавление можно в любой момент кнопкой «✖️ Отменить».

Бот работает **длинным опросом**: сам ходит в Telegram за сообщениями. Отдельный
домен, вебхук и открытый порт для него не нужны — он поднимается вместе с сайтом
в том же контейнере.

### Смена номера WhatsApp

Номер, на который приходят заказы, меняется прямо из телеграма: **⚙️ Настройки →
📱 Изменить номер WhatsApp**. Дальше бот сам всё сделает:

- принимает номер в любом виде — `+992 90 140 32 63`, `992446007080`, `(44) 600-70-80`.
  Лишние знаки убирает сам;
- девять цифр без кода страны дополняет кодом Таджикистана `992`;
- показывает, что получилось, и ссылку `wa.me/номер` — **проверьте номер здесь**,
  пока не нажали «Сохранить», настройки не трогаются;
- после сохранения предлагает показать этот же номер на сайте как контактный.

**Заказы уходят на новый номер сразу.** Даже если покупатель открыл сайт до смены и
не перезагружал страницу: сервер возвращает актуальный номер в ответ на заявку, и
кнопка ведёт уже на него. Перезапускать магазин не нужно.

### Статистика посещений

Считаются только просмотры страниц живыми людьми — главной и карточек букетов.
Запросы к API, картинки и поисковые роботы отбрасываются, иначе один заход
выглядел бы как двадцать. Один человек за день считается один раз.

**IP посетителей нигде не хранится.** От него берётся необратимый отпечаток —
кусок SHA-256 от адреса, браузера, даты и случайной соли этой установки. Он нужен
ровно для одного: понять, что два просмотра за день сделал один человек. Назавтра
отпечаток того же посетителя уже другой.

История держится 90 дней и лежит в `data/stats.json`. На диск пишется раз в
полминуты, а не на каждый заход.

«Сегодня» считается по часовому поясу магазина — `SHOP_TZ` в `.env`, по умолчанию
`Asia/Dushanbe`. Без этого день начинался бы в 5 утра по местному времени.

| `server.js` | Сервер, API, авторизация, SEO-разметка |
| `store.js` | Хранилище: чтение и запись каталога, проверка данных. Общее для сайта и бота |
| `bot.js` | Панель управления в Telegram |
| `stats.js` | Счётчик посещений сайта |
| `seo.js` | Заголовки, описания, адреса букетов и разметка Schema.org |
| `public/` | Витрина, страница букета, админ-панель |
| `test/` | Проверка бота, счётчика, оформления заказа и SEO: `npm test` |
| `data/` | Каталог, настройки, заявки и статистика в JSON |
| `uploads/` | Загруженные фотографии |
| `Dockerfile`, `docker-compose.yml`, `Caddyfile` | Запуск на сервере с SSL |
| `deploy.sh` | Установка и обновление одной командой |

### Технологии

Node.js · Express 5 · Multer · Docker · Caddy · Telegram Bot API без библиотек · чистый HTML/CSS/JS без фреймворков

---

## Безопасность

- Пароль администратора хранится в `.env`, а не в коде
- Вход выдаёт временный токен сессии на 12 часов
- Защита от подбора пароля: 10 попыток за 15 минут с одного адреса
- Все поля товара проверяются на сервере, ссылки на фото — только `http(s)` и свои загрузки
- Заголовки безопасности и Content-Security-Policy включены
- Запись каталога атомарная — сбой сервера не повредит данные

---

## Производительность

- Ответы сжимаются gzip/brotli
- Фотографии кэшируются на год, статика — на неделю
- Главная страница грузит всё одним запросом `/api/bootstrap`
- В сетке каталога подгружаются уменьшенные версии фото
- Ссылки на букеты отдают превью с фото и ценой при отправке в WhatsApp
